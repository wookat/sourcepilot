## 二、新发现问题清单（P1×2 / P2×10）

### P1（影响信息可读/演示主链路）

**P1-1 固定操作列挤压相邻列，内容被截断为 1–2 字（1440 视口，多页复现）**
- 库存中心：「库存状态」右侧「规格绑定」列仅剩「已/无/未」单字（截图 `inventory-center-1440.png`）
- 失败任务中心：「店铺」列截断为「DE…」无 ellipsis/Tooltip（`taskcenter-failures-1440.png`）
- 订单列表：「支付」列 Tag 右缘被固定列边界裁切（`orders-1440.png`）
- 商品草稿/AI 工作台：「创建/更新时间」列截断为「2026-0…」（`product-drafts-1440.png`、`ai-workbench-1440.png`）
- 根因判断：R66 收口的是固定列阴影与 768 禁用口径，未定义「非固定列 minWidth + ellipsis + Tooltip」兜底策略；列多的页面在 1440 下剩余空间被固定操作列吃掉。
- 建议：TmProTable 层统一给非固定列设 minWidth 并默认 `ellipsis: { showTitle: true }`；操作列 >3 动作收敛为「更多」下拉（同时缓解异常工作台 7 链接一行的拥挤）。

**P1-2 刊登任务页开箱双 Tab 空态（seed 演示缺口）**
- `/product/publish-tasks` 子任务、刊登批次均空，与 R75「刊登链路演示样本」目标不符（seed counts 无 publish_tasks/publish_batches 行）。新手运营者从菜单进入「刊登任务」看到的是完全空页面，演示链路断点。
- 建议：seed:demo:full 补 1 个刊登批次 + 2–3 条子任务样本（含 1 条失败）。

## 三、与 Shopify Admin 类竞品对照 — Top5 低成本改进建议（antd token/配置级）

1. **表格列宽与截断策略统一收口（对应 P1-1）**：Shopify Admin 表格所有列均有 min-width 且截断必带 Tooltip。TmProTable 统一注入 `ellipsis: { showTitle: true }` + 列级 minWidth 默认值，操作列 >3 动作收敛「更多」Dropdown。纯组件配置，无 API 变更。
2. **时间列短格式**：Shopify 列表用相对/短时间（"Yesterday at 3:12 pm"）。表格内时间统一 `MM-DD HH:mm`（Tooltip 展示完整 formatDateTime），可节省约 40% 列宽，直接缓解 1440 挤压。formatDateTime 旁加一个 formatDateTimeShort 即可。
3. **状态语义全覆盖巡检（对应 P2-2/3/4）**：把「运营任务执行状态、草稿来源、客服平台列」接入既有 StatusTag/PlatformTag 集中映射，并给 `check:ui-copy` 加英文枚举直出检测规则，防止后续页面再漏。
4. **移动端首页信息分层（对应 P2-6/7）**：待办卡默认只展示前 5 条 + 「查看全部」；批量工具栏未选中时隐藏（`alwaysShowAlert: false` 口径）。Shopify 移动端首页仅 1.5 屏核心指标 + 任务入口。
5. **图表轴标签自适应（对应 P2-5）**：chartTokens 增加 x 轴 `tickCount`（按容器宽度 6–10 档）与 MM-DD 短标签；与既有 useWideScreen/heightCompact 同一模式，配置级落地。
