## 三、R135–R142 新能力是否坐实矩阵位置（本轮核心验证）

1. **自动打标签（R135 #282）→ 第 6 项坐实**：标签管理页（3 标签）、订单列表标签筛选与批量打标、自动化规则「自动打标签」动作全部实测在位；operator 触发 DEMO-AT-1005 后日志出现「打标签 DEMO-大客户 成功」。R125 识别的马帮动作粒度差距（发货规则/分仓/打标签）至此三项全部补齐并真实触发验证。
2. **备份对象存储（R138–R142 #287/#290）→ 第 16 项增强**：S3 兼容 Provider + 保留策略 + 恢复取回 + 4 条安全加固合入 main；未配 S3 时 API 层显式降级口径（见矩阵第 16 项），符合「不伪造接通」原则。UI 层 `/ops/backups` 等三页对 demo 租户 admin 显示「暂无访问权限」——经代码核对（`router.go` `RequirePlatformAdminMW`），/ops/* 属平台租户专属，**属权限边界设计而非回退**；建议 demo 走查文档标注该口径（见五-1）。
3. **消息规则回溯口径（#291）→ 未合入，不计入本轮矩阵**：PR #291（买家自动消息默认不回溯存量+可选回溯+预估确认）截至本轮仍 OPEN。本轮仅验证 main 现状（两 tab 非空、不自动外发声明在位、无回退）；#291 合入后属第 12 项体验强化，不改变评级。
4. **工程强化不改变评级但支撑可信度**：UX v9 收口（CSV 平台列中文化、「未折算」显式口径本轮导出层实测确认）、大回归 v20/v21 零 P0/P1、升级演练季度复检、验收包增量 R136–R140——「达到/超越」项的可复核性持续加强。

### 2. 新缺口审视

逐项对照后，**没有发现新的结构性产品能力缺口**。按性质分类：

- **平台覆盖长尾（增项 18，凭证依赖）**：店小秘美客多全托管、马帮 TikTok 美区认证/巴西 NFe——均为特定平台/区域通道，对当前抖店/TikTok/Shopee 主线单卖家非必需。
- **外部数据源依赖**：AutoDS ShopShark Winning Ads/创作者数据需 TikTok 广告与达人数据源；与我方选品外部大盘同类，凭证/数据源到位前不可做也不必做。
- **原生 APP 深度**（马帮亚马逊 APP）：我方移动 H5+PWA 覆盖关键动线（本轮 375 实测通过），原生 APP 属长期项，维持 AGENTS.md 轻量口径。
- **趋势信号（非缺口，机会）**：AutoDS 在 MCP 上从「connector 发布」到「Q2 主打」持续加码，验证 R134 判断：「对话式操作 ERP」正在成为行业交互范式。我方开源自托管 + MCP 是竞品（SaaS 封闭）难以复制的差异化位置，该机会时效性上升。

## 五、实测发现项（非阻断，已登记）

1. **/ops/* 权限口径需在走查文档显式**：demo_admin（租户 1）访问 /ops/backups、/ops/restores、/ops/disaster-recovery 显示「暂无访问权限」。经代码核对为设计（平台租户专属），非缺陷；建议 `demo-fullstack-walkthrough` SKILL 与 DEMO_SCRIPT 标注「备份/恢复/容灾演示需平台管理员账号（ADMIN_BOOTSTRAP，tenant 0）」，避免复评/演示时误判为回退。
2. **自动化日志时间格式不统一**：/orders/automation-logs 显示 `2026/8/6 15:01:22`（斜杠格式），与全站 `YYYY-MM-DD HH:mm` 口径不一致（UX v9 已统一标签页，此页漏网）。P2 级，建议并入下轮 UX 巡检。
3. **#291 待合入**：消息规则回溯口径 PR 尚未合入 main，合入后建议在下次复评中带一次实测确认。

## 六、下一阶段路线建议（如无异议按此执行）

**结论：连续两个 8 轮维护期（R126–R133、R135–R142）均零回退、矩阵 0 落后，产品侧「随时可验收」状态稳定。建议正式转入「低强度维护 + 差异化小步」双轨，凭证到位即插队真实 E2E。**

### 凭证未到位期间值得做的纯产品增强（按杠杆排序）

| 序 | 建议 | 一句话理由 |
|----|------|-----------|
| 1 | MCP/对话式只读查询入口（订单/库存/报表/自动化日志查询，写操作保持人工确认） | AutoDS 半年内两次加码 MCP 验证范式成立，我方开源自托管接 MCP 是竞品结构上做不到的差异化，且只读实现小、风险低 |
| 2 | 实时经营大屏（站内数据秒级刷新视图层） | R130 聚合已下推 SQL，只差展示层；对齐店小秘 2026-06 大屏，演示/验收价值高、零凭证依赖 |
| 3 | 发现项收口小轮：automation-logs 时间格式 + /ops/* 演示口径文档化（本报告五-1/2） | 保持零 P2 积压与走查证据自足，半天级投入 |
| 4 | 买家消息多语言模板（R125 清单最后余项） | 既有规则×模板基建上的小增量，补齐清单收尾；#291 合入后顺路带回溯口径实测 |
| 5 | 备份 S3 全链路 demo 化（本地 MinIO 容器演示上传/取回/保留策略） | 把 R138–R142 的能力从「测试兜底」升级为「可演示」，强化第 16 项验收证据，无外部依赖 |

### 建议进入低强度维护的项

- **大回归/UX 复评**：由每轮改为每 4–6 轮或有合入面时触发（连续两个维护期零 P0/P1，边际收益递减）。
- **升级演练/依赖审计**：维持季度节奏即可（R132/R137 已两次复检通过）。
- **竞品复评**：改为每 12 轮或竞品出现结构性动作时触发（连续三次复评 0 落后且无新结构缺口）。
- **明确不做**（维持 R134 判断）：视频翻译、以图搜SKU、区域报关/开票（美客多全托管/巴西 NFe 类平台长尾）、原生 APP——除非老板明确方向。

**正式验收口径**：维持 R134 建议——当前预验收包满足沙箱口径验收条件；真实平台口径唯一前置仍是外部凭证五项（抖店/1688/电子面单/TikTok/Shopee）注入后的真实 E2E 轮。
