# Round 151 线1：大回归 v24 P2×2 收口 + MCP fail-closed 提示巡检

日期：2026-08-07。承接大回归 v24 报告（PR #303 评论登记）P2 清单与 R151 线1 任务。基线：最新 main（合至 #302）；#303/#304/#305 尚未合并，本轮改动面（McpTokens 页审计加载时序、AutomationLogs 空态、docs/mcp.md 审计段落）与三者 diff 无文件级冲突，其中 docs/mcp.md 审计口径按 #303 的 fail-closed 行为撰写（见 §3）。

## 1. P2-1 审计卡片轻刷新时序（v24 登记：工具调用后首次轻刷新偶现「暂无数据」，整页刷新正常）

- 根因：`McpTokens.tsx` 的审计加载无并发保护——手动「刷新」与筛选/翻页 effect 触发的加载可重叠，迟到的旧响应会覆盖后发请求的结果，旧响应恰为空列表时表现为闪回「暂无数据」。
- 修复：`loadAudits` 增加请求序号护栏（`auditSeqRef`），仅最后一次发起的请求可写入 `auditRows`/`auditTotal`/`auditError`/`auditLoading`，迟到的旧响应直接丢弃。
- 回归：新增 `admin/src/pages/Settings/__tests__/McpTokens.test.tsx`——两笔并发审计请求乱序返回（后发先回、先发迟到且为空），断言不闪回「暂无数据」；已验证该用例在修复前失败、修复后通过。

## 2. P2-2 readonly 店铺 scope 空态（v24 登记：readonly 账号因店铺权限范围看不到 DEMO-AT-1004）

- 后端 `ListAutomationLogs` 按店铺 scope 过滤（`adminperm.ApplyStoreScope`），行为正确；缺口在前端：`Orders/AutomationLogs.tsx` 空态为裸文案「暂无执行日志」，无权限范围提示。
- 修复：沿既有 F7 空态引导口径接入 `useListEmptyLocale('automationLogs', { permissionScoped: true })`，`LIST_EMPTY_COPY` 新增 `automationLogs` 条目（标题/说明/「前往自动化规则」动作 + 统一 `PERM_HINT` 店铺权限提示；readonly 账号自动隐藏动作按钮）。

## 3. MCP 审计写失败 fail-closed 提示巡检

- 后端（#303，未合并）：审计行写入失败时成功结果被扣下、调用返回 `audit log unavailable, tool call rejected`，并记 Error 日志 `mcp_tool_audit_write_failed`。
- 巡检结论：管理页对审计列表加载失败已有错误 Alert + 重试按钮，口径可用；但 `docs/mcp.md` 仍写「best effort，审计库故障不影响工具调用本身」，与 fail-closed 行为相反——本轮改为 fail-closed 口径，并在故障排查表新增 `audit log unavailable, tool call rejected` 行（含恢复/重试指引与管理页表现）。该文档口径依赖 #303 合入生效，若 #303 回退需同步回改。
