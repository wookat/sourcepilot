# R153 线1：R152 两新功能（开放 API / 多语言模板）交叉 QA + 安全审查

范围：在最新 `main` 上按序本地叠加 #308（开放 REST API + `mcp_api_tokens.purpose`）→ #309（买家消息多语言模板 + regenerate），做攻击面专项测试，P0/P1 直接修复。

## 修复（本轮 P1）

1. **被禁用/清退租户的 API token 仍可读数据**（`mcptoken.AuthenticateFor`）
   后台 JWT 在租户 `status=disabled` 时返回 `401 AUTH_TENANT_DISABLED`，但 MCP / 开放 API token 不查租户状态，被清退租户仍能通过 token 持续读取订单、库存、异常与经营摘要。修复：token 鉴权统一调用 `auth.EnsureTenantActive`（租户状态不可判定时按失败处理，与 JWT 口径一致），两个入口一并生效。

2. **伪造 `X-Forwarded-For` 可绕过每 IP 鉴权失败预算**（`TRUSTED_PROXIES`）
   gin 默认信任所有代理，客户端 IP 取自请求头，轮换该头即可无限次尝试 token（每 IP 401 预算 1 r/s、突发 10 形同虚设），同源问题也影响登录、邮件验证码与全局限流的每 IP 口径。修复：新增 `TRUSTED_PROXIES`（逗号分隔 IP/CIDR，默认空=不信任任何代理，客户端 IP 取 TCP peer 地址），启动时 `SetTrustedProxies`，非法值 fail-fast。部署在唯一入口代理之后时才填该代理 IP。

3. **开放 API 审计 fail-open，与 MCP（#303）fail-closed 口径不一致**（`openapi.audited`）
   审计写失败仅 `slog.Warn` 并照常返回数据，存在“读到数据但无审计”的调用。修复：响应先缓存，审计行落库成功后才输出；审计存储不可用时丢弃结果并返回 `500`（只读接口可安全重试）。与 #303 的 MCP 口径一致（#303 合入后两入口同为 fail-closed）。

回归测试：`mcptoken/tenantstate_test.go`（禁用租户两入口均拒绝）、`openapi/audit_failclosed_test.go`（审计存储不可用时不泄露查询结果）。

## 已验证无问题（Docker 双租户实测）

- purpose 越权矩阵：mcp token → 开放 API 401；openapi token → `/api/mcp` 401；both 双通；空 purpose（历史行）仍仅 MCP。
- 跨租户/未知订单一律 404，不可区分；`tenantId` 等查询参数不能覆盖 token 绑定的租户。
- 输出脱敏：客户名首字符 + `**`，无邮箱/电话/内部 UUID/rawData/凭证字段。
- 限流：每 token 桶、租户聚合桶（多 token 不放大）、两入口独立桶、非法日期 400、关键字 `ILIKE` 参数化无注入。
- regenerate 越权：readonly 403、跨租户 404、非法 uuid 400、非 pending 400、语言白名单外 400（含注入串）、无变体语言 400；不外发、逐次写操作日志。
- 模板变量替换单趟完成（买家昵称内含 `{订单号}` 不会二次展开），缺失变量记入 `missingVars`；HTML/脚本样本按纯文本存储与 JSON 转义返回。
- 语言推断：US→en、BR→pt（`order_country`），无国家回退 `fallback`。
- seed clean → verify 零 `DEMO-` 残留（含 `customer_reply_template_variants`）。

## 遗留（P2，未修）

- both 用途 token 在两入口各占一份额度，实际可得 2 倍聚合额度（文档已声明桶独立，需评估是否按租户合并）。
- 401/429 请求不写审计行，暴力尝试与限流事件在审计表不可见（仅日志）。
- 开放 API 分页参数非法值（`page=abc`、`pageSize=-1`）静默归一化，而日期非法返回 400，参数校验口径不一致。
- operator 角色对未授权店铺的草稿 regenerate 返回 404（店铺可见性），与 readonly 的 403 口径不同，排障时易误判。
- `mcptoken.Create` 仍为 count→insert 非原子（token 上限竞态），#303 已含修复，未合入 `main`。
