# R160 线1：R159 审计 P2 收口（fullstack-engineer）

- 目标：收口 `docs/SECURITY_AUDIT_R159.md` 登记的 P2 清单（view-only persona 缺口、非法入参静默降级、40301/40303 业务码不统一、前端构建链 13 条依赖告警）。

- 依赖：叠加 R159 P1 修复提交（`032d1ae0`，即 PR #322 的 view-only 授权写入修复）——本轮 view-only persona 契约测试依赖该修复才能通过；#322 合入 main 前本 PR 不可独立合入。#311/#317/#318/#319/#321 与本轮改动面无交叉。

## P2-1 权限矩阵补 view-only persona（✅）

- harness 新增可选 persona `viewOnlyOperator`（tenant A operator，唯一店铺授权为专用店铺的 `view` scope），机制同 `platformAdmin`（matrix.json 显式声明才参与路由级探测）。
- 新增契约测试 `permmatrix/view_only_persona_test.go`：全部 `/orders/:id*`、`/order-items/:itemId*` 写路由 + 买家消息草稿写路径（update/regenerate/mark-sent/ignore）断言 view-only → 403 + 业务码 40303 + 零落库；带路由完整性检查（新增此类路由未登记探针即失败，防再漂移）；纯计算 POST（`sku-candidates/batch`）与订单读保持 200。
- 文档：`docs/permission-matrix.md` 新增「round160」章节。

## P2-2 非法入参静默降级 → 显式 400（✅）

- 共享只读查询层（Open API 与 MCP 共用）`readonlyquery` 新增 `ParseEnum`：`orders` 的 `status`/`paymentStatus`、`exceptions` 的 `exceptionType`/`severity` 非法值 → `ErrBadInput`（HTTP 400 / 40001），合法值与空值行为不变；校验先于服务可用性检查。
- Open API `lowStockOnly` 改严格布尔（`true`/`false`/`1`/`0`，空缺为 false），其余值 400/40001（沿 #303/#312 的日期/分页口径）。
- 全站扫描：普通 admin API 的枚举/布尔入参走 Gin binding 或显式 switch（非法值已 400），日期/分页/排序沿 R154 收口后的口径，未发现其他静默降级点；MCP 工具经同一 `readonlyquery` 层收敛。
- 回归测试：`openapi/r160_bad_input_test.go`（7 组非法入参断言 400+40001，5 组合法值断言 200）。
- 契约/文档：`docs/openapi/open-api.v1.json` 补齐 `status`/`paymentStatus`/`exceptionType` 枚举并把 `severity` 由漂移的 `error/warning` 更正为 `low/medium/high/critical`；`docs/open-api.md` 新增枚举/布尔 400 口径说明。

## P2-3 40301/40303 业务码统一（✅）

- 取舍：店铺级「可见但仅 view 授权」的 403 统一为 `40303 CodeStorePermissionDenied`（R125 商品线与 `adminperm.DenyStorePermission` 既有口径，语义最精确）；`40301 CodeForbidden` 保留给全局/租户级 forbidden（readonly 账号写操作、跨租户 settings、生产闸门等），`40302` 保留给权限位拒绝。
- 改动面：order（handler/tag/tracking/sku_match/print_workbench/automation）、customerchat 买家消息草稿、finance 对账/费用的店铺操作拒绝由 40301 → 40303。
- 前端无按 40301/40303 分支的逻辑（`httpErrorCopy` 按 HTTP 403 文案），契约 fixtures 无引用；`docs/permission-matrix.md` 同步说明。
- 回归：view_only_persona_test 全部写探针断言 40303。
