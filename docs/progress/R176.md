## 1. 修复（先红后绿）

1. **P1-1 迁移导入目标店铺缺租户闭合**：`migrationimport.resolveShop` 对 admin 跳过全部店铺校验且从未在租户内确认店铺存在，跨租户 admin 用他租户 `shopId` 可通过 `/imports/validate`（200 + 逐行校验结果）与 `/imports/commit`（200 + 写出携带外租户 `shop_id` 的 `import_jobs` 行）。改为统一 `adminperm.ApplyTenantScope` 加载目标店铺，外租户/不存在 → 404「店铺不存在或不可见」。
2. **P1-2 `PUT /api/v1/settings` 可把已加密密钥降级为明文**：`settings.putOne` 的加密与否完全取决于请求体 `isEncrypted`，省略即明文落库并覆盖 `is_encrypted`，后续 `GET /settings` 原文回显。改为加密粘性 `encrypted := it.IsEncrypted || (exists && cur.IsEncrypted)`，已加密项无法被请求体降级。
3. **P2-1（一并修）回复面与 bind-sku 校验顺序**：`customerchat.MarkReplied` / `SendPlatformMessage`、`orderexception.BindSKU` 仍先校验 body 再结算店铺 scope，view-only 拿到 400 载荷错误。三处改为 scope 先答：view-only → 403 + 40303，不可见 → 404，可操作店铺保留 400。

回归测试（均先红后绿）：`securitytests/permmatrix/r176_scope_order_test.go`（3 例）、`modules/settings/r176_encryption_sticky_test.go`（1 例）、`modules/mcpserver/r176_purpose_test.go`（补 purpose 反向隔离覆盖缺口：`openapi` 用途 token 打 MCP 入口 401、`both` 放行）。
