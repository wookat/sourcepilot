## 1. 实现：服务端声明式敏感 key 注册表

- 新增 `settings/sensitive_registry.go`：`IsSensitiveKey(groupKey, itemKey)` / `RegisterSensitiveKeys(groupKey, keys...)`（大小写不敏感）。注册来源（声明式汇总，非按 key 名启发式，避免误加密 `*_access_key_id` 等展示项——注册表按各 schema 的 `Sensitive` 声明逐 key 精确登记）：
  1. 包 init 静态注册：`IntegrationConfigDefinitions()` 中 `Sensitive: true` 的字段（ai / image / storage / mail / alert_notify 共 24 键，含 legacy `ai/api_key`）＋ legacy `email/smtp_password`。
  2. 平台凭证：`api.Register` 在全部平台 provider 注册完成后，把每个 provider 的 `AppConfigSchema` / `PublishConfigSchema` 中 `Sensitive` 字段汇入注册表（`internal/api/sensitive_settings_keys.go`，覆盖 `platform_*` 全组：app_secret / partner_key / client_secret / consumer_key|secret / refresh_token 等）。
- `settings.putOne` 加密判定改为 `it.IsEncrypted || (exists && cur.IsEncrypted) || IsSensitiveKey(gk, ik)`：注册表项**新建即强制加密落库**，读回显走既有 List 脱敏 / `PlainByGroup` 解密链路，口径不变。非注册表项保持客户端声明兼容（显式 `isEncrypted:true` 仍可加密；R176 加密粘性不变）。
- `APP_MASTER_KEY` 未配置时保存注册表项返回既有 400 中文提示（fail-closed，不明文落库）。
