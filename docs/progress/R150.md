## 1. deploy-prod.sh 重跑丢 compose override 挂载（R149 P2）

问题：脚本固定 `docker compose -f docker-compose.prod.yml`，上次部署时手工 `-f` 叠加的 override（如把 `BACKUP_S3_CA_BUNDLE` 自签 CA 挂进 backend）在重跑时丢失，backend 启动 fail-fast `CONFIG_INVALID: BACKUP_S3_CA_BUNDLE unreadable`。

修复（`scripts/deploy-prod.sh`）：

- 仓库根存在 `docker-compose.prod.override.yml` 时自动叠加（按机器维护、已加入 `.gitignore` 不入库），重跑（升级/回滚重建）不丢挂载。
- 也可 `COMPOSE_OVERRIDE_FILES=a.yml:b.yml` 显式指定多个 override（冒号分隔），文件缺失时 fail-fast 退出。
- compose 校验步骤打印最终 compose 命令，便于核对 override 是否叠加。

文档同步：`docs/production-deployment.md`（日常升级补 override 口径）、`docs/env.md`（BACKUP_S3_CA_BUNDLE 挂载口径）、`docs/upgrade-guide.md`（重跑升级注意项）。

Docker 重跑演练（证据外置 `~/r150-evidence/`，不入库）：localhost 全栈生产部署，override 挂 fake CA + `BACKUP_S3_CA_BUNDLE=/etc/trademind/backup-s3-ca.pem`；首跑成功且 backend healthy、容器内可读 CA；重跑 `--no-pull` 自动叠加 override，挂载保持、HTTPS 探活通过；基线 compose（无 override）confirm 无该挂载（原 bug 场景）；`COMPOSE_OVERRIDE_FILES=missing.yml` 按预期 fail-fast。
