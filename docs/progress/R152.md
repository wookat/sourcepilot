# Round 152 线1：对外开放 REST API（只读起步）

竞品复评 v7 路线①第一杠杆（店小秘/马帮均有开放 API 体系）。

## 内容

1. **开放 API 只读入口** `GET /api/open/v1/*`（`backend/internal/modules/openapi`）：订单列表/详情、库存查询、经营摘要、异常待办 5 个 GET 端点，仅注册 GET，无任何写操作。`OPENAPI_ENABLED`/`OPENAPI_RATE_RPS`/`OPENAPI_RATE_BURST` 配置。
2. **token 治理复用**：不另建 token 体系，`mcp_api_tokens` 新增 `purpose` 字段（`mcp` 默认/`openapi`/`both`）做入口选择器，`scope` 保持单一 `readonly` 轴；存量 token 视为 MCP 用途，不能访问新入口（攻击面不变宽）。哈希校验/过期/吊销/每租户 20 上限/三层限流（token/租户聚合/IP 鉴权失败预算，桶与 MCP 独立）/逐次审计（工具名 `openapi:<endpoint>`，不记参数与结果）全部沿 MCP 口径。
3. **共享只读查询层** `backend/internal/modules/readonlyquery`：MCP 4 工具与开放 API 5 端点共用同一查询实现与 DTO（防两面漂移），新增订单详情（按订单号，跨租户与不存在统一 404）。输出脱敏：客户名仅首字符，无内部 UUID/邮箱/电话/rawData/凭证字段。
4. **管理页**：token 创建可选用途（MCP/开放 API/两者），列表新增用途列（`McpTokens.tsx`、`mcpTokens.ts`）。
5. **契约**：OpenAPI 3 规范 `docs/openapi/open-api.v1.json`；Go 契约测试 `spec_test.go`（spec 路由 ↔ 实现路由、schema ↔ DTO 字段双向同步校验）；`tests/contracts/api-contracts.json` 登记 5 端点 + purpose 字段。权限矩阵登记 5 路由（`probe:false`）。demo seed 补开放 API 演示 token（`fulldemo_round147.go`）。
6. **文档**：新增 `docs/open-api.md`（curl 示例/错误码表/限流说明）；同步 `docs/api.md`、`docs/mcp.md`、`docs/env.md`、`docs/permission-matrix.md`、`docs/module-map.md`、`.env.example`、`.env.docker.example`。

## 验证

`gofmt`/`go vet`/`go test ./...`（openapi/mcptoken/mcpserver/demoseed/permmatrix）、`pnpm test:contracts`、`pnpm test:frontend`、`pnpm build:admin`；Docker 双租户实测（跨租户 401/404、readonly 语义、限流 429）证据不入库。

# R152 线2：买家消息多语言模板（跨境多语种买家）

## 目标

复评 v7（`docs/COMPETITIVE_BENCHMARK_R151.md` 路线②）建议项：话术/消息模板支持多语言变体，买家消息草稿按订单/店铺目标语言选择变体，人工确认发送口径不变（绝不自动外发）。

## 交付内容

### 1. 模板多语言变体（backend/internal/modules/customerchat）

- 新表 `customer_reply_template_variants`（`tenant_id + template_id + language` 唯一，变体正文 ≤4000 字符）；`customer_reply_templates` 新增 `default_language`（缺省 `zh-CN`，既有 `content` 即默认语言正文，历史数据零迁移兼容）。
- 语言表可扩展（`template_lang.go`）：`zh-CN/en/es/pt/fr/de/it/ru/ja/ko/th/vi/id/ms/ar`；变量占位符 `{变量}` 口径与默认正文一致。
- 模板 API 新增 `defaultLanguage`、`variants`（传 `variants` 时事务内全量替换）；校验语言合法/不重复/内容非空；按租户隔离，跨租户 404。

### 2. 草稿语言选择与切换（buyermsg）

- 生成草稿时按优先级推断目标语言：①订单 `RawData` 收货地国家（`order_country`）→②店铺默认语言（`shop_language`）→③店铺平台（`platform`）→④无法推断回退模板默认语言并标 `fallback`；推断出语言但缺变体时用默认正文标 `no_variant`。
- 草稿 DTO 新增 `language` / `langSource`（含 `manual`），语言选择全程可解释。
- 新端点 `POST /buyer-messages/drafts/:id/regenerate`（body `{language}`）：仅 `pending`，按所选语言重填订单变量重新生成，成功后 `langSource=manual`；只修改草稿，不触发任何外部发送；写权限沿 `adminperm.CanWriteCustomer`（readonly 403），跨租户 404，记 operation log。
- 幂等/不覆盖既有草稿/人工确认发送等既有口径不变。

### 3. Admin UI（全中文管理界面，模板正文可为外语）

- 话术模板页：语言列展示默认语言+变体语言标签；编辑弹窗支持默认语言选择与语言变体增删改，带变量占位符指引。
- 待发消息工作台：语言列展示语言与推断来源（含「无法推断，已回退默认语言」「缺该语言变体，已回退默认语言」标注）；编辑弹窗可选语言「按所选语言重新生成」，明确「仅改草稿，不会向买家发送」；readonly 全部写控件禁用。

### 4. Demo seed（clean/verify 覆盖）

- 话术模板补英/西/葡变体样本；正样本 `DEMO-BM-1005`（US→en）、`DEMO-BM-1006`（BR→pt），负样本 `DEMO-BM-1001`（无国家→zh-CN fallback）。
- Cleanup/VerifyClean 覆盖 `customer_reply_template_variants` 零残留，重跑幂等。

### 5. 测试与门禁

- 后端：`template_lang_test.go`（语言正规化/国家提取/推断优先级/变体选择/CRUD 校验/regenerate/生成语言口径/租户隔离）+ 既有 fixture 同步；`go fmt/vet/test/build` 全绿。
- 契约：`tests/contracts/api-contracts.json` 补 regenerate 端点与模板 upsert 新字段（受保护端点 117）。
- Admin E2E：`round152-multilang-templates.spec.ts`（模板语言列/变体维护 payload 校验、草稿推断来源与回退标注、切换语言重新生成写请求拦截、readonly、五档视口无横向溢出），8/8 通过。
- `pnpm check:dev`、`check:ui-copy --strict`、`test:frontend`、`test:contracts`、`build:admin` 全绿。
