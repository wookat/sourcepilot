# Round 162 线1：MCP 写操作白名单设计稿（决策项，纯文档）

日期：2026-08-07。承接 R161 复评建议 2（`docs/COMPETITIVE_BENCHMARK_R161.md` §六）：AutoDS Claude MCP 已含写操作，出「写白名单设计稿」供老板决策；**本轮只出方案，不实现任何写操作，不改任何代码行为**。

## 交付物

- `docs/design/MCP_WRITE_WHITELIST_PROPOSAL.md`：完整设计稿，含
  1. 竞品调研（AutoDS 写范围与「账号直通」模型、Shopify 生态三层闸门/schema 限额/confirm 参数等最佳实践、店小秘/马帮无 MCP 入口确认）；
  2. 候选写操作清单 W1–W18（沿订单闭环梳理，L1–L4 风险分级；P0 最小集 = W1 订单打标 / W2 异常标记 / W3 mark-placed / W4 采购物流回填 / W5 mark-paid 带金额上限）；
  3. 安全模型：`write:ops` 独立 scope（与 `readonly` 单轴兼容演进，存量 token 零变化）、环境+租户+scope 三层默认关闭闸门、强制 dry-run→confirmationToken→execute 状态机、逐次审计（fail-closed 沿用，写操作记参数摘要）、三层幂等、业务限额、租户/店铺 scope 复用 `EnsureStoreOperable` 口径、审单闸门优先于 MCP、「绝不自动外发」红线延续（消息线零 MCP 触点）；
  4. 分阶段落地（P0 约 2.5 轮含安全验收；P1/P2 触发式）与「不做清单」（刊登/外发/删除/权限管理/批量写等永久或本期不做）；
  5. 决策请求 D1–D4（明确建议采纳 P0、不采纳对齐 AutoDS 直接刊登）。

## 结论与立场

建议采纳 P0 最小集路线；不建议照搬 AutoDS 直接刊登写范围（与「绝不自动外发」红线冲突且凭证未解锁）；不建议在 readonly scope 上打补丁旗标；不建议任何免确认执行模式。实现工作待老板批准后另开轮次，前置依赖 #322（view-only P1 修复）先合入。
