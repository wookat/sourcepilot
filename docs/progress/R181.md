# R181 线1：MCP 写白名单 W3 收尾（第 2.5/2.5 轮）

承接 R179 W1 基建与 R180 W2 三动作（见 `docs/progress/R179.md`、`docs/progress/R180.md`），本轮把最后一个 P0 写动作 `mark-paid` 按 brief 三前提接入 W1 框架，并对 W1+W2+W3 全写面做渗透视角安全交叉审查。

## 本轮交付

### `procurement_mark_paid` 接入 W1 框架（`backend/internal/modules/mcpserver/write_tools_r181.go`）

- `placed → paid` 人工付款回填，走既有状态机 `transitionTx`（`procurement/mcp_write.go` 新增 `MarkPaidInTenantTx` / `AfterMarkPaidCommitted`）；**不动真实资金**，仅登记操作员已线下支付的事实（Mock provider 推进 + 操作日志与后台人工路径同口径，事务提交后执行）。
- 复用 W1 全套管道：三层闸门、dry_run→一次性确认 token→execute、参数哈希绑定（金额/币种/渠道均入哈希）、fail-closed 审计、次数限额、跨租户/不存在统一 404。
- brief 三前提，全部 fail-closed：
  1. 租户金额上限必须先配置：设置项 `mcp/mark_paid_single_limit`（单笔）+ `mcp/mark_paid_daily_limit`（日累计），缺失/非数字/0/负数一律视为未配置 = 工具不可用，403 语义并审计。
  2. dry_run 预览回显金额、币种、上限、当日已用额度与采购单全明细行（商品/SKU/数量/单价）。
  3. 金额/币种与采购单不一致直接拒绝：金额按「分」整数比较（>0、至多两位小数，超两位小数/NaN/超大金额判非法入参），币种大小写不敏感精确匹配。
- 日累计额度按当日成功 execute 审计行金额求和（审计模型新增 `amount` 列，AutoMigrate 覆盖），并在 **execute 事务内**重跑全部前提——dry_run 领到的确认 token 不能绕过其后被占满的额度（TOCTOU 封死）。

### W1+W2+W3 全写面安全交叉审查

- 渗透视角逐项核对 18 个攻击面（token 伪造/重放/跨 token/跨租户消费、闸门绕过、readonly/openapi 越权、跨租户写、审计缺记录、次数与金额限额绕过、金额边界 0/负数/精度/币种混淆、状态机绕过、外发红线），**未发现 P0/P1**；报告归档 `docs/SECURITY_AUDIT_R181_MCP_WRITE.md`（含 2 项 P2/建议级观察：并发限额竞态、审计 amount 列口径）。
- 新增跨租户确认 token 消费显式回归（`TestMarkPaidConfirmationCrossTenantRejected`）。
