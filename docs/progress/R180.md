# R180 线1：MCP 写白名单 W2（第 2/2.5 轮）

承接 R179 线1 W1 基建（write:ops scope / 三层闸门 / dry-run→确认 token→执行 / fail-closed 审计限额 / 订单打标，见 `docs/progress/R179.md`），本轮补齐后台治理 UI 与三个 P0 写动作，并处理 R179 线2 遗留的 Shopee partner_key 敏感注册。

## 本轮交付

### 三动作接入 W1 框架（`backend/internal/modules/mcpserver/write_tools_r180.go`）

- `exceptions_mark`：异常标记。`action` 为 `handle`（已处理）/ `ignore`（已忽略）/ `unmark`（清除标记），复用 `orderexception` 既有 `handled`/`ignored` 标记语义（不发明第三种持久化状态）；幂等（重复同向无新行、handle↔ignore 互斥切换、unmark 空标记为无操作）。租户内源解析（订单/订单项等 sourceType），跨租户 / 不存在统一「记录不存在」（404 口径）。
- `procurement_mark_placed`：采购单回填 1688 外部单号，复用既有状态机 `placing → placed`（`transitionTx`），非法状态在 dry_run 即拒绝；跨租户 / 不存在统一「采购单不存在」。
- `procurement_fill_logistics`：物流运单号回填，`paid → shipped` 并创建 `purchase_logistics` 行（运单号 + 承运商）；同一状态机 / 404 口径。
- 三工具全部走 `mcpwrite.Service.Run`：dry_run 返回结构化影响预览 + 一次性确认 token；execute 的业务变更与审计行同事务（为此 procurement 抽出 `transitionTx` 事务内变体、orderexception 抽出 DB 参数化的 scope/pointer 解析）；mock provider 注册 / 操作日志 / 自动化事件等副作用移至事务提交后（`After*Committed`），与后台人工路径同口径。
- `mark-paid` 刻意不接入：留待 W3 与「租户金额上限 + 三前提」一起落地（permmatrix note 同步登记）。

### 后台治理 UI（`admin/src/pages/Settings/McpTokens.tsx`）

- 「MCP 写白名单」卡片仅 admin 可见（operator/readonly 完全不渲染、不拉取设置）：
  - 租户级 `mcp / write_enabled` 开关：默认关；开启前弹风险确认（受控 Modal，说明三层闸门与全局 `MCP_WRITE_ENABLED` 的关系）；关闭直接落盘。
  - 写 token 创建 / 吊销：独立列表只展示 `write:ops` token；创建走 `scopes:['readonly','write:ops']`，有效期仅默认(30)/7/30/90 天，无「不过期」；明文仅创建后展示一次。
  - 审计表新增「模式 / 参数摘要 / 确认哈希」三列（`mode` / `paramsSummary` / `confirmHash`），读工具行显示为「—」。
- 后端同步收紧（`mcptoken/handler.go`）：非 admin 的 token 列表过滤掉写 token；非 admin 吊销写 token 返回 404（不可见即不可操作）；只读 token 行为不变。
- 审计 API（`mcpaudit/handler.go`）补出 `mode` / `paramsSummary` / `confirmHash` 字段（模型中 W1 已落库）。
