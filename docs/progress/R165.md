# R165 线1：view-only 店铺授权写入口全站扫尾（fullstack-engineer）

日期：2026-08-07。背景：#322（订单/草稿）、#330（客服会话族）两次发现同类越权漂移——写路径复用「可见性 scope」（`AllowedStoreIDs`/`ApplyStoreScope`/`EnsureStoreVisible`），而 view-only 授权的店铺**可见**，导致写操作被放行。本轮一次性系统排查全部带 shop_id 维度的写接口，统一收口为「可见性管读、可操作性管写」：写路径必须走 `EnsureStoreOperable`/`EnsureStoresOperable`/`ApplyStoreOperateScope`（view-only → 403 业务码 40303；不可见/跨租户 → 404 不泄露存在性）。基线叠加 #330 分支（`fix/round164-line2-viewonly-conversation-writes`，未合并），PR 注明依赖。

## 1. 全站排查结果与修复面

逐模块梳理 shop_id 写接口（含经订单/商品/采购单/发布记录/任务行间接关联店铺的写路径），本轮收口的漏洞面：

| 模块 | 漏洞写路径（收口前仅校验可见性/租户） | 修复 |
| --- | --- | --- |
| ordersync | `POST /shops/:id/sync-orders`、任务 retry | 手动同步会**创建任务并回写业务行**，定性为写：`EnsureStoreOperable` |
| customersync | `POST /shops/:id/sync-customer-messages`、任务 retry | 同上（R164 P2-4 口径正式定案：收口到 operate，见 §3） |
| inventory | 同步任务创建（发布 SKU / 商品×店铺）、retry、批量筛选与批量 retry | `EnsureStoreOperable` / `ApplyStoreOperateScope`（批量按可操作店铺过滤） |
| inventorysyncp9 | `POST /inventory-sync/runs`（编排/幂等/事务前） | APIActor 增加 `OperableShopIDs`，写路径校验可操作 |
| productpublish | 任务创建、retry、取消、目标草稿、抖音建品草稿、SKU 同步/手动绑定/解绑、卡死恢复 | `EnsureStoreOperable`（经发布记录→父商品+目标店铺解析） |
| operationtask | 创建、取消、草稿提交等写路径 | APIActor 增加 `OperableShopIDs`，写 scope 与读 scope 分离 |
| orderexception | `handle`/`ignore`（经 source 行解析回店铺） | 新增 source→shop 解析 + `EnsureStoreOperable` |
| procurement | mark-placed/cancel 等采购单写路径、路由级与批量写 | 经关联销售订单店铺 `EnsureStoresOperable`；批量按可操作店铺过滤 |
| taskcenter | 委托 retry（order_sync/customer_message_sync/inventory_sync/product_publish） | 透传底层 403/40303 映射 |
| order review | `POST /order-review/approve|reject` | 整批前置 `ensureReviewBatchOperable` + 行级 `EnsureStoreOperable`（任一 view-only 行 → 整批 403/40303，见 §4 取舍） |
| shop | 店铺 Update/Delete、`PUT /shops/:id/auth`、OAuth refresh/revoke/callback/sync-shop-info | 新增 `findScopedShopForWrite`/`ensureShopOperable`；OAuth 连接测试类只读路径保持可见性口径 |

统一错误映射：`adminperm.FailStoreWriteScope`（404 记录不存在 / 403+40303 店铺无操作权限）接入以上各 handler，避免误落 400/500。

已核对无漏（已有 operate 口径或非店铺维度）：订单写路由与草稿（#322/R160）、客服会话族（#330/R164）、自动化/审单/消息规则 shopIds 与 dry-run/日志（R164）、财务对账/费用（R160）、商品创建（R125）、迁移导入、物流规则（试算为纯计算只读白名单，发货推荐解析走可见性只读）。

## 2. 回归测试（先红后绿）

- **permmatrix 新增 `view_only_sweep_test.go` `TestViewOnlyPersonaShopWriteSweep`**：30 条写探针（手动同步入口、四类任务 retry、任务中心委托 retry、运营任务创建/取消/草稿、订单异常 handle/ignore、采购 mark-placed/cancel、店铺记录/凭证/OAuth 写、P9 run 创建）对 view-only 授权断言 403 + 40303；审单 approve/reject 断言整批 403/40303 且 review_status 不翻转；不可见店铺同资源 404；**零落库断言**（任务状态不变、无新建任务/运营任务/P9 run）；读路径（同步任务/运营任务详情）保持可用。修复前该测试对上述各面全红，修复后全绿。
- **matrix.json 补全 view-only persona 契约行**：为 shops/order-sync/message-sync/inventory-sync/product-publish/task-center/operation-tasks/orders/order-items/order-review/procurement/customer 系非 GET 探测路由补 `viewOnlyOperator` 期望共 113 条（路由级探测防未来漂移；数据级 403/40303 由专项契约测试承担，口径同 R160 设计）。
- 前端新增 `permission.test.ts` 用例：admin 全可操作、readonly 全不可、operator 混合授权（view/operate/manage）仅 operate/manage 可操作。

## 3. R164 P2 收口

- **P2-2/P2-3（前端一致性）**：`admin/src/utils/permission.ts` 新增 `operableStoreIds`/`canOperateAnyStore`/`canOperateStore`（与后端 `Principal.OperableStoreIDs` 同口径），`usePermission` 暴露。会话列表页：readonly/view-only（无可操作店铺）隐藏「新建会话/拉取平台消息」及空态动作；写表单店铺选择器仅列可操作店铺。会话详情页：「废弃建议」补 `readOnly` 禁用（其余写按钮 R164 已禁用）。后端 403 仍为最终边界。
- **P2-4（message-sync 口径定案）**：手动订单同步与客服消息同步**定性为写操作**——两者都会创建同步任务并 upsert 订单/会话/消息业务行，非纯读；统一收口到 operate（view-only → 403/40303）。文档更新 `docs/api.md`、`docs/permission-matrix.md`。

## 4. 取舍与说明

- **审单批量 API 沿 R165 线2（#331，已合入 main）整批前置校验**：`/order-review/approve|reject` 在写入前经 `ensureReviewBatchOperable` 整批检查，任一 view-only 行即整批 403/40303（避免部分生效）；不可见行仍保持行级「订单不存在」不泄露存在性。本分支合入 main 时与 #331 口径合流，sweep 测试已改为断言整批 403。
- **OAuth authorize-url / 连接测试保持可见性口径**：不落业务数据、不改凭证，属读类操作；callback/refresh/revoke/sync-shop-info 落凭证或店铺信息，收口 operate。
- worker/队列内部路径传 nil gin context 信任（任务创建入口已收口）。
