## 修复（本轮 P1）

**P1-1 仅 `view` 授权的店铺可被写入（同租户内店铺授权粒度越权写）**

`permission_scope='view'` 的 operator 对该店铺的订单与买家消息草稿仍可写（修复前实测草稿 `PUT` 返回 200 且内容被改写）。根因：R149–R158 新增/改造的写路径只校验店铺「可见性」，未校验「可操作性」；R125 商品创建线已确立 view-only 必须 403 的口径，本批未跟随。

口径（与 R125 一致）：可见但只 `view` → 403（`ErrStoreNotOperable`）；不可见 / 跨租户 / 不存在 → 404（不泄露存在性）；admin 与 `operate`/`manage` 不受影响；被拒写入零落库。

实现：`adminperm` 新增 `Principal.OperableStoreIDs()`、`EnsureStoreOperable()`、`ApplyStoreOperateScope()`；`order` 新增 `findOrderOperable()` + `failOrderWriteScope()`；`customerchat` 新增 `findTenantDraftForWrite()`。覆盖：草稿编辑 / regenerate / mark-sent / ignore / 批量；订单创建（含指定 `shopId`）、更新（含改 `shopId` 迁店）、删除、行项与发货单增删改、手工与批量打标、物流刷新、自动化失败重试、扣减/回滚库存、SKU 匹配与 `bind-sku`、打单标记。

回归：`backend/internal/securitytests/permmatrix/buyermsg_draft_operate_scope_test.go`（修复前失败：期望 403 实得 200 且草稿被改；修复后全绿，并断言 `operate` 店铺写入仍 200、view-only 记录零变更）。Docker 实测（临时降级授权后还原）全部 403。
