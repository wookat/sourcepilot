## 【改动明细】

### 1. 服务端值域校验（backend/internal/modules/settings/）

- 新增 `value_registry.go`：受控值域注册——`validateControlledValue` 在 `Service.putOne`（`PutBulk` 事务内逐项调用）持久化前校验：
  - 仅接受 `^[0-9]+(\.[0-9]{1,2})?$` 的十进制数字（大于 0、至多两位小数）；科学计数法（`1e20`/`1e5`）、正负号（`-1`/`+500`）、千分位（`1,000`）、十六进制（`0x10`）、`NaN`/`Infinity`/非数字/尾部杂字符一律拒绝；
  - 上界 `1e10`（100 亿）＝ `amountCents` 对单笔金额的硬上界，超过即拒（超过该值的上限等同于不设限）；
  - 空值/清除合法（= 未配置，消费侧 `markPaidLimits` fail-closed）；存储前去除首尾空白；
  - 这两个 key 不允许 `isEncrypted` 加密存储（加密行会被消费侧 `ParseFloat` 失败视为未配置，等于静默失效）；
  - 错误文案为中文、点名 key 并说明值域（400 语义经由现有 settings 错误链路返回）。
- 批量原子性：`PutBulk` 单事务内任一项非法即整体回滚，合法兄弟项不落库。
- 回归测试 `r189_markpaid_limit_validation_test.go`（先红后绿）：14 组非法值 × 2 key（含 `1e20`、`99999999999999999999`、`10000000000.01`、`-1`、`0`、`NaN`、`Infinity`、`abc`、`12.345`、`1e5`、`0x10`、`+500`、`1,000`、`500x`）写入被拒且零行落库；批量含非法项回滚；合法值（`0.01`/`500`/`500.5`/`2000.00`/`1e10` 上界/带空白）通过且落库；加密存储拒绝；空值/清除合法；错误文案点名 key + 中文值域说明。
- 币种口径：限额与采购单金额同为「租户本位币数值」，不新增币种字段；精度与 `amountCents` 一致（分级两位小数）。

### 2. UI 同步校验（admin/src/pages/Settings/McpTokens.tsx）

- `MARK_PAID_LIMIT_MAX = 1e10` 常量（注释指向服务端注册表），单笔/日累计两个 `InputNumber` 增加 `max`，表单 rules 增加 `type: 'number', min: 0.01, max: 1e10` 与中文提示「须在 0.01 到 100 亿之间（至多两位小数）」；原 `min=0.01`/`precision=2` 保留。
- 测试：新增用例——输入 `99999999999999999999` 提交后不允许把超过 1e10 的值发给服务端（InputNumber 在 blur 钳制到上界，双保险为服务端 400）。
