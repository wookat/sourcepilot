# Round 143 线1：备份定时器 / 生产恢复演练开关 / 恢复取回覆盖 / 自签 CA 配置项

日期：2026-08-06。承接 R142 线2 演练报告 P2 清单（#287/#290 备份对象存储实现面）。

## 1. 内置备份定时器（BACKUP_SCHEDULE + BACKUP_SCHEDULE_ENABLED）

- 新增 `backend/internal/pkg/backupsched`：零依赖计划解析器，支持 5 字段 cron（`*`、单值、范围、步长、逗号列表、周日 7→0）与简化 interval（`@every 6h` / `6h`，最小 1 分钟）。
- `BACKUP_SCHEDULE_ENABLED=true` 时 backend 启动内置定时器（`backup.StartScheduler`，随 worker 生命周期优雅退出），按计划走完整备份流（pg_dump、加密、checksum、manifest、S3 上传重试、对象保留策略）。
- 幂等：备份记录新增 `triggerSource`（manual/scheduled）与分钟精度 `scheduleKey` 唯一索引；同一触发时隙重复触发返回既有 job，不重复跑备份。
- 失败可见：失败落 `status=failed` + `errorSummary`（经脱敏），Ops 备份页可查看；失败时隙保持占用，不会在同一时隙重复重试。
- 未配置/未启用保持现状：`BACKUP_SCHEDULE` 仅为元数据，宿主机 crontab 保留为备选路径；文档口径从「crontab 推荐」改为「内置定时器推荐、crontab 备选」。
- 启动校验：启用定时器时非法表达式、`BACKUP_ENABLED=false` 或 `BACKUP_MODE=disabled` 均 fail-fast。

## 2. 生产恢复演练开关（BACKUP_RESTORE_ALLOW_PRODUCTION）

- production AppEnv 下 `POST /ops/restores` 与 `POST /ops/restores/:id/verify` 默认拒绝（`RESTORE_APP_ENV_FORBIDDEN` / `RESTORE_VERIFY_APP_ENV_FORBIDDEN`）；显式设 `BACKUP_RESTORE_ALLOW_PRODUCTION=true` 才允许隔离恢复演练。
- 开关放行后仍保留全部既有护栏：目标必须 `trademind_p6v_restore_*` 隔离库、目标库必须为空、操作者重认证 + 高危二次确认、备份必须 completed+verified+checksum+manifest 校验、永远禁止恢复到 `production` 目标环境。
- 权限矩阵：restore 全部路由仅平台管理员（tenant 0）可用，`restore.execute`/`restore.verify` 写操作对 readonly/operator/业务租户一律 403（`securitytests/permmatrix/matrix.json` 契约测试覆盖）。
- 新增回归：`backend/internal/modules/restore/production_gate_test.go`。

## 3. 恢复路径对象存储取回自动化覆盖（#290 修复面）

- 新增 `backend/internal/modules/restore/object_fetch_test.go`：本地产物丢失（容器重建场景）时 `runPgRestore`/`Verify` 自动从对象存储取回、checksum 校验通过并继续恢复；对象副本也缺失时明确失败。
- 既有 backup 侧覆盖（verify 取回、路径越界拒绝）保留不变。

## 4. 自签 CA 显式配置项（BACKUP_S3_CA_BUNDLE）

- 新增 `BACKUP_S3_CA_BUNDLE`（PEM 路径）：备份 S3 客户端在系统信任库基础上额外信任该 bundle，替代仅靠容器挂载合并系统 CA 的约定；路径不存在或非法 PEM 在启动与 Store 构造时 fail-fast。
- 文档写清差异：本地/内网 production-like MinIO 演练才需要自签 CA（证书只读挂载进 backend 容器 + 填容器内路径）；真实生产对象存储用公信 CA，留空即可。
