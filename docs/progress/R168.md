## 任务1：店铺权限拒绝文案统一「店铺无操作权限」

所有 `40303 CodeStorePermissionDenied` 用户可见 message 统一为「店铺无操作权限」，收口点：

| 位置 | 原文案 |
|---|---|
| `backend/internal/pkg/adminperm/deny.go` `DenyStorePermission` | 当前账号无权访问该店铺数据 |
| `backend/internal/pkg/security/authorize.go` `Deny` 的 `ErrShopAccessDenied` 分支 | 当前账号无权访问此店铺 |
| `backend/internal/pkg/tasktenant/context.go` `ErrTaskShopScopeMismatch` 分支 | 当前账号无权访问此店铺 |
| `backend/internal/modules/product/service.go` `ErrDraftShopNotOperable` | 当前账号无权访问该店铺数据 |

前端 toast 走 envelope message 自动一致；审单 tooltip/预禁用文案（`Orders/Review/index.tsx`）已为「店铺无操作权限」。全站 grep 确认无残留同类不一致；有意保留的不同语义文案：全局权限「当前账号无权限执行此操作」、只读账号、租户不匹配、不可见店铺/资源不存在（404 不泄露存在性）、AI 模型权限。`docs/permission-matrix.md` 已补 round168 条目。

## 任务3：刊登 target 完全不带 shopId 的口径（登记，不改行为）

**现状**（`productpublish/publish_targets.go`、`batch_targets.go`）：

- 前置权限校验 `ensureTargetsOperable` 对 `shopId` 为空的 target 直接跳过（不校验、不拒绝）。
- 执行阶段 `sid == nil` 时该 target 记为 `failed` 结果行，`ErrorMessage: "缺少店铺"`；请求整体仍返回 200 envelope，批次/审计中留 failed 行。

**两种口径对比**：

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 请求级 400 拒绝（含任一无 shopId target 即整体拒绝） | 入口即挡、无脏批次；与「整批 403」审单口径风格一致 | 混合批中合法 target 一并被拒；属行为变更，需前端配合与回归 |
| B. 现状：200 + failed 审计行 | 不阻断合法 target；审计留痕可追溯；零改动 | 无 shopId target 静默失败，调用方若不看结果行易漏 |

**推荐**：倾向 A（请求级 400），理由：target 无 shopId 属于构造错误请求而非运行时失败，入口拒绝语义更清晰，且与 R167 审单整批拒绝的定案风格一致；若老板选 A，建议下一轮实施并同步 `docs/api.md` 与前端提交前校验。**本轮不改行为，待老板决策。**
