# R182 线1：MCP 写面遗留 P2 收口（并发限额硬保证 + 审计 amount 口径 + W2 UI 缺口）

> 基线：叠加在 R181 W3 分支（PR #363，未合并）之上，目标 main。

## 背景与范围

R181 安全审查（docs/SECURITY_AUDIT_R181_MCP_WRITE.md）遗留两个 P2：

1. **并发 execute 限额竞态**：次数 / 金额限额的读判断发生在 execute 事务内（PostgreSQL READ COMMITTED），并发下多个事务可同时读到未含彼此的计数，各自通过判断后一起提交，导致超过上限。
2. **审计 `amount` 字段口径**：`amount` 仅对金额型写动作（`procurement_mark_paid`）有意义，其余写动作恒为 0；审计 API/UI 若不加说明展示，0 可能被误读为金额。

另有 R180 遗留 W2 UI 缺口（审计列表筛选 / 展示不全）与 R179–R181 合入面巡检。

## 1. 并发限额硬保证（P2 #1）

### 设计

`mcpwrite.Service.runExecute` 的限额事务串行化，按租户两层：

- **进程内**：`Service.tenantLocks`（`sync.Map` → 每租户一把 `sync.Mutex`），执行事务全程持有；覆盖 SQLite 等非 PostgreSQL 路径。
- **跨进程（PostgreSQL）**：事务级 advisory lock `SELECT pg_advisory_xact_lock(hashtext('mcpwrite_execute:<tenantID>')::bigint)`，在事务内所有限额读判断（token 时次数、租户日次数、mark-paid 金额日累计）之前获取；加锁失败 fail closed 拒绝执行。

锁按租户隔离，不同租户互不阻塞；dry_run 不加锁（只发确认 token，不消耗额度）。

### 先红后绿并发回归测试

`backend/internal/modules/mcpwrite/concurrency_test.go`（`postgrestest.Require` 隔离 schema，需 `APP_ENV=test` + `TEST_DATABASE_URL`，库名含 test 安全校验）：

- `TestExecuteCountQuotaRacePostgres`：预填 199 条成功 execute 审计行后 8 个并发 execute 抢最后 1 个名额，断言恰好 1 成功 7 拒绝，审计行数不超过 200。
- `TestExecuteAmountCeilingRacePostgres`：模拟 mark_paid 事务内金额日累计校验（单笔 88、日上限 150），8 并发断言恰好 1 成功，累计金额不超上限。
- `TestExecuteTenantIsolationRacePostgres`：双租户并发——租户 1 处于最后名额被硬限、租户 2 全部通过，验证锁与额度不跨租户泄漏 / 阻塞。

先红：修复前 8/8 全部通过（证据 red-quota-race.txt）；后绿：加锁后 `-count=3` 稳定通过（green-quota-race.txt）。均在 Docker PostgreSQL（docker-compose 的 trademind-postgres 容器）上实测。

## 2. 审计 amount 口径收口（P2 #2）

- 后端审计 API DTO（`GET /api/v1/mcp/audit-logs`）补 `amount` 字段（`omitempty`，非金额型动作缺省）。
- 后台审计列表新增「金额（仅支付登记）」列：仅金额型动作显示金额，其余显示「—」，列头 Tooltip 说明「仅 procurement_mark_paid 有金额」，避免 0 被误读。
- docs/api.md、docs/mcp.md 同步登记口径。

## 3. W2 UI 缺口补齐

- 审计筛选补「调用模式」（dry_run / execute）筛选：后端 `ListFilter.Mode` + query 参数 `mode`，前端 Select。

- 金额列见上。前端单测补金额列 / 口径断言（McpTokens.test.tsx），后端补 `TestListFilterByMode`。

## 后续风险

- 进程内租户互斥使同租户 execute 完全串行；写限额本就为低频人工确认操作（200 次/天），吞吐影响可忽略。若未来多副本部署且弃用 PostgreSQL，需要等效跨进程锁。
- `hashtext` 存在理论上的租户键哈希碰撞（碰撞仅导致两租户互相串行，不影响正确性）。
