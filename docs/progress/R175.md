## 1. P2① 登记的 7 处 modal rethrow 收口

公共根源一并收口：

- 新增 `admin/src/utils/modalOk.ts`：`modalOk(run, errorText?)` 构造非 async `onOk(close)`，成功才 `close()`，失败 `message.error(中文)` 且不向外抛拒绝；附单测 `modalOk.test.ts`（4 例）。
- `admin/src/utils/sensitiveConfirm.tsx`：`confirmSensitiveAction` 的 `onOk` 由「async + 吞错（失败仍自动关弹窗）」改为 `onOk(close)` 手动 close 口径，并新增 `errorText` 定制失败文案；附单测 `sensitiveConfirm.test.tsx`（2 例）。全站 `confirmFailureTaskRetry`/`confirmInventorySync`/`confirmCustomerReplySend`/`confirmChangeUserRole`/`confirmAssignStorePermissions`/`confirmInventoryManualAdjust` 等 helper 同步透传 `errorText`。

登记 7 处逐一收口（回调内去掉 `throw e`，失败由 helper 统一 toast+保持弹窗）：

1. TaskCenter/Failures：详情抽屉「重试任务」`confirmFailureTaskRetry` 去 rethrow；忽略/已处理标记、生成告警（列表+抽屉）、批量忽略/批量已处理、抖店尝试恢复共 7 个静态 confirm 改 `modalOk`。
2. Settings/Users：改角色（外层 confirm + 内层敏感确认双弹窗改 close 链）、店铺权限保存去 rethrow；启用用户裸 `void promise.then` 补 `.catch` toast。
3. Product/DraftDetail：批量预警线（外层受控 Modal + 内层 confirm 的 resolve/reject 包装改 close 口径）、批量库存同步 `confirmInventorySync` 去 rethrow、单规格同步 Modal 去 Promise 包装、删除草稿改 `modalOk`。
4. Inventory/SyncTasks：批量重试失败去 rethrow。
5. Inventory/Alerts：单规格同步、批量同步批次、人工修正库存、批量预警线（内层 confirm）全部改 close 口径；预警线设置 `validateFields` 未兜底的拒绝补 catch。
6. Customer/ConversationDetail：取消关联订单/店铺（原失败无 toast 且弹窗照关）改手动 close + 中文失败 toast；平台发送去 rethrow。
7. Settings/Security（R174 未列但同清单页）：撤销会话/撤销其它会话/全部登出改手动 close。

## 2. P2③ 全站防漏扫描（同类模式一并收口）

`rg "onOk: async|onOk={async|throw e"` 全站复扫，除登记 7 处外一并收口：

- 静态 confirm async onOk（失败自动关弹窗）：TaskCenter/Alerts×5（发送通知/已处理/忽略/取消标记/扫描）、Ops/Releases×2（执行发布/回滚）、Ops/Backups（创建备份）、Procurement（作废采购单）、Settings/PlatformTenants×3（启用/停用/清退）、Shops（删除店铺，原失败无 toast）→ 全部改 `modalOk`。
- 受控 `<Modal onOk={async}>` 的 `await form.validateFields()` 未兜底拒绝（dev overlay 同类泄漏）：Ops/Releases、Ops/DisasterRecovery、Procurement/Detail×4、Sourcing/ProductSources、Orders/Detail×2、Orders/index×3（其中明细/物流保存原无任何 catch，失败静默）、TransferStockModal、DraftDetail 预警线 → 补 catch/return；Orders 明细/物流保存补中文失败 toast。
- 复扫后 admin 无 `onOk: async` 静态 confirm 残留、无 modal 链路 `throw e` 残留。

## 3. P2② migrationimport 向导 shape 英文串中文化

沿全站结构化中文口径（保留参数名便于排查，与同函数「必填字段「%s」未映射到任何列」等既有措辞一致）：

- `service.go`：`columns is required` → 「表头列（columns）不能为空，请先上传并解析导入文件」；`rows is required` → 「数据行（rows）不能为空，导入文件至少需要一行数据」；`mapping is required` → 「字段映射（mapping）不能为空，请先完成字段映射」；`fileHash is required` → 「文件指纹（fileHash）不能为空，请重新上传导入文件」；顺带 `shopId is required（…）` → 「归属店铺（shopId）不能为空，导入必须选择归属店铺」、`invalid shopId` → 「归属店铺（shopId）无效」。
- `progress.go`：进度查询 `fileHash is required` → 「文件指纹（fileHash）不能为空」。
- `mappings.go`：映射方案保存 `mapping is required` → 「字段映射（mapping）不能为空」。
- 全站无代码/测试字符串依赖旧英文串（`TestMigrationImportScopeBeforeBody` 只断言状态码），无契约漂移。
