# R154 线1：R153 安全审查 P2 批次收口

范围：基于 #308 → #309 → #311 叠加分支（`fix/round154-audit-p2`），逐项处理 R153 线1 安全审查遗留 P2（含与 #303 重复覆盖项的核实登记），并补齐 #311 三个行为变更的文档面。

## 逐项处理结果（P2×6）

### 1. 401/429 请求不写审计行 —— 已修复

暴力猜 token 与限流事件此前只在日志可见，审计表无痕。修复：MCP 与开放 API 两个入口的鉴权中间件在 401/429 时写入口级审计行（工具名 `mcp:auth` / `openapi:auth`，状态 `auth_failed` / `rate_limited`）：

- 未认证来源（缺失/非法 token、鉴权失败预算触发的 429）记在租户 0 下，仅记录来源类别，不记录任何 token 内容；
- 已认证后的限流（token 桶 / 租户聚合桶）归属对应租户与 token（脱敏）。
- 防审计表放大：按「工具+状态+来源」每分钟至多一条（进程内节流，多副本下每副本各一条，量级仍受控）；写入为 best effort，不阻断错误响应（错误路径无数据泄露，与成功路径 fail-closed 的动机不同）。
- 管理页「MCP 只读接入」审计筛选同步新增两个状态与两个工具名。

回归测试：`openapi/p2_hardening_test.go`（401 落 `auth_failed`、429 落 `rate_limited`、节流不放大）、`mcpserver/authaudit_test.go`、`mcpaudit/throttle_test.go`。

### 2. 开放 API 分页非法值静默归一化 —— 已修复

`page=abc`、`pageSize=-1`、`page=0` 等此前静默按默认值执行，与日期非法返回 400 的口径不一致。修复：`page`/`pageSize` 非整数或非正数统一返回 `400`（`40001`）；缺省仍取默认值，超过 100 的 `pageSize` 保持按 100 截断（文档已声明的契约）。orders / inventory / exceptions 三个分页端点一并生效。

回归测试：`openapi/p2_hardening_test.go` `TestPaginationInvalidValuesAnswer400`。

### 3. both 用途 token 双入口双份额度 —— 登记不改（需产品决策）

`both` token 在 MCP 与开放 API 各有独立限流桶（policy 前缀 `mcp_readonly*` / `openapi_readonly*`），实际可得约 2 倍聚合额度。合并需要决策额度语义：按租户跨入口合并会让重度 MCP 使用挤占开放 API 集成的额度（反之亦然），也可能需要新配置项。文档（`docs/open-api.md`）已明示两入口桶相互独立，租户内聚合桶已防多 token 放大，风险为额度口径而非安全绕过。留待产品决策后另行收口。

### 4. operator 未授权店铺 regenerate 返回 404（与 readonly 403 口径不一）—— 登记不改（有意为之）

核实（`customerchat.findTenantDraft` → `adminperm.EnsureStoreVisible`）：operator 对店铺范围外草稿返回 404 是店铺可见性口径——不向未授权角色泄露草稿是否存在，与跨租户 404 同理；readonly 的 403 是角色级写拒绝（不涉及具体资源存在性），二者语义不同。将 404 改为 403 会泄露未授权店铺下资源的存在性，属于安全性回退。保持现状，此处登记以免后续审查重复报告。

### 5. `mcptoken.Create` count→insert 竞态 —— 跳过（#303 已覆盖）

#303（R149 安全 P2 批次）已将创建改为事务 + per-tenant 锁并附并发回归测试，且已合入 `main`（本分支合并 main 后已包含该实现），本轮不重复实现，该项闭合。

### 6. MCP 审计写失败仅告警不阻断（fail-closed） —— 跳过（#303 已覆盖）

同上：#303 已将 MCP 工具调用审计改为 fail-closed，与 #311 中开放 API 的口径对齐，且已合入 `main`（本分支合并 main 后两入口同为 fail-closed，`docs/mcp.md` 已为 fail-closed 口径），该项闭合。注意：入口级 401/429 拒绝留痕（本轮新增）仍为 best effort——请求本身已被拒绝，审计写失败不改变响应。
