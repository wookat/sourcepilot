# R179 线1：MCP 写白名单 W1 基建（第 1/2.5 轮）

## 决策口径（定案）

- **D1**：P0 最小写动作集，首个动作为订单打标（addTag/removeTag）；异常标记、mark-placed、物流回填、带三前提的 mark-paid 后续轮次接入。
- **D2**：独立 `write:ops` scope，readonly token 不放宽、开放 API 面不放宽。
- **D3**：三层闸门默认全关（全局 `MCP_WRITE_ENABLED` / 租户设置 `mcp/write_enabled` / token scope）+ 强制 dry-run→一次性确认 token→执行。
- **D4**：fail-closed 审计 + 限额；operator 不可管写 token；写 token 默认过期（30 天，最长 90 天，不支持不过期）。

## 本轮交付

### Token 治理（`backend/internal/modules/mcptoken`）

- `write:ops` 作为独立 scope 轴：`NormalizeScopes` 拒绝未知/空 scope（fail-closed）；MCP 入口接受 `readonly` 或 `write:ops` 成员，开放 API 入口仅接受 `readonly` 成员。
- `CreateScoped`：scope 只能创建时授予，无升级入口；写 token 强制过期（默认 30 天 / 最长 90 天）；`openapi` 用途不可携带 write scope。
- Handler：带 `write:ops` 的创建仅 `admin` 角色（`adminperm.LoadPrincipal`），operator/readonly 返回 403；创建/吊销继续走操作日志。

### 写管道（新模块 `backend/internal/modules/mcpwrite`）

- `Gate`：全局（env）+ 租户（settings `mcp/write_enabled`，读取失败即关）两层闸门；第三层 scope 在 mcpserver 注册期与管道内双重校验。
- 确认 token：`mcp_write_confirmations` 表只存 SHA-256；绑定「租户 + 调用 token + 工具 + 参数哈希」四元组；TTL 5 分钟；`UPDATE ... WHERE consumed_at IS NULL` 原子消费；缺失/过期/复用/换调用者/参数漂移一律拒绝；执行成功后重放返回 `alreadyExecuted=true` 不重复变更。
- 审计 fail-closed：dry_run 的确认发放与审计行同事务；execute 的限额校验、业务变更、审计行、executed 标记同事务提交，审计失败整体回滚（`audit log unavailable, tool call rejected`）。
- 限额（按成功 execute 审计行计数，计数失败即拒绝）：每 token 30 次/小时、每租户 200 次/天。

### 首个写动作（`backend/internal/modules/mcpserver/write_tools.go` + `order/mcp_tag_write.go`）

- `orders_add_tag` / `orders_remove_tag`：单目标（一个订单号 + 一个已存在标签名）；幂等（重复打标 `applied=0`、移除不存在 `removed=0`）；跨租户/不存在统一「订单不存在/标签不存在」（404 语义，无存在性探测）。
- dry_run 返回结构化 preview（当前标签、change=add/remove/none）+ 人话摘要。
- 消息线零 MCP 写触点：白名单仅上述两个工具，`TestNoExternalSendToolExposed` 断言全量工具面。
