## 三、两个差异化杠杆是否坐实「超越」（本轮核心验证）

### 1. MCP 只读入口（R144–R148）→ **坐实「超越」（对可比竞品）**

本轮协议级端到端实测（Docker 全栈，demo_admin 租户）：

- **token 治理链**：登录 → `POST /api/v1/mcp/tokens` 创建（`expiresInDays:7`）→ 明文仅一次返回 + 列表脱敏 `sp_mcp_ro_dc09…0e00` ✅
- **MCP 协议**：`POST /api/mcp` Streamable HTTP `initialize`（serverInfo `sourcepilot-readonly`）→ `tools/list`（四只读工具中文描述 + JSON Schema 完整）→ `tools/call orders_query`（客户名脱敏 `D**`）→ `report_summary`（订单/销售额/异常/低库存聚合，多币种不折算口径）✅
- **审计与边界**：两次 tools/call 后 `GET /api/v1/mcp/audit-logs` 逐次落库（工具名/状态/耗时，不记参数结果）✅；无效 token → 401 ✅；入口无任何写工具（by design）。

竞品对照：**店小秘、马帮（可比的国内跨境 ERP 双雄）截至 2026-08 均无任何 MCP/AI 助手对话式入口**（官网/博客/帮助中心复查无相关能力）。AutoDS 有 Claude MCP connector（2026-07 发布、Q2 主打，含直接刊登等写操作），但 AutoDS 为 SaaS 封闭托管、面向 dropshipping 细分；我方定位差异：**开源自托管 + 租户级 token 治理（哈希存储/过期/吊销/三层限流/逐次审计）+ 只读安全边界**，这是 SaaS 竞品结构上不提供的组合。结论：第 19 项增项评「▲超越」成立（对店小秘/马帮），且经 R145 安全交叉审查 + R148 季度审计双重把关，证据链完整。

### 2. 实时经营大屏（R145 #296）→ **「达到/齐平」，不宣称超越**

我方实测：`GET /api/v1/dashboard/screen` 单次聚合（无 N+1），今日 KPI/待办五类分级深链/7 天漏斗/24h 趋势/告警，深色投屏页 15/30/60s 轮询，权限双 scope fail-closed，多币种「未折算」显式口径（不伪造汇率）。

店小秘对照（help.dianxiaomi.com/article/dataAnalytics/3349、blog/article/540，2026-06 上线）：秒级刷新、**16+ 平台真实订单数据源**、店铺/平台 TOP10 排行、销售地图、今日/昨日双线对比、**外币按下单时汇率统一折算 CNY**。

诚实评估：视图层能力（KPI/趋势/待办/投屏）我方齐平且待办深链+权限工程更严谨；但店小秘优势在**多平台真实数据源**（我方属凭证依赖项，非产品差距）与**汇率折算口径**（我方为「不伪造」原则显式不折算——可通过可配置汇率源补齐，见第六节建议 3）。结论：第 11 项证据面增强、维持「▲边缘」；大屏单项记「达到」，不作为超越宣称。

### 2. 三个定向方向的缺口审视

- **AI 助手集成**：店小秘/马帮仍无跟进（其 AI 布局集中在美图/视频翻译/文案，属内容生产而非对话式操作入口）；AutoDS MCP 已含写操作（直接刊登）。**无新缺口；我方 MCP 只读领先可比竞品一个身位，写操作白名单是保持身位的下一步（需产品决策）。**
- **开放 API**：**既有结构性差距候补确认**——马帮开放平台开发者体系成熟（应用管理/审核/发布流程 + 订单/商品/库存/海外仓全域 API），店小秘支持 REST API 类店铺授权集成；我方无对外 REST API。对自托管开源产品，「可编程集成」是核心买点之一，且 MCP 的 token 治理/限流/审计基建可直接复用，实现成本已大幅摊薄。**列为 R152+ 第一优先。**
- **数据大屏**：店小秘大屏无进一步迭代；我方视图层齐平（见三-2）。差距两点均有明确路径：汇率折算（可配置汇率源，中成本）与多平台数据源（凭证依赖，不可做也不必做）。**无结构性缺口。**

其余（视频翻译/AI 美图升级/美客多全托管/NFe/原生 APP/达人建联）维持 R134/R143 判断：平台覆盖长尾、内容生产增值或凭证/数据源依赖，非结构性缺口，维持「明确不做」清单。

## 六、下一阶段路线建议（R152+，按杠杆排序；如无异议按此执行）
